# Установка на сервер, где уже есть продакшен

Основная инструкция ([INSTALL.md](INSTALL.md)) рассчитана на выделенную машину:
там свободны 80 и 443, а firewall, SSH и sysctl принадлежат только VPN.

На сервере с чужими сервисами это не так. Режим `SHARED_HOST=yes` меняет поведение:

| Что | Выделенный сервер | `SHARED_HOST=yes` |
|---|---|---|
| firewall (nftables) | настраивается | **не трогается** |
| харденинг SSH | применяется | **не трогается** |
| sysctl, BBR | применяется | **не трогается** |
| перезапуск docker | да, после firewall | **нет** — иначе перезапустит чужие контейнеры |
| reverse proxy | поднимается свой Caddy | используется существующий |
| привязка портов панели | `127.0.0.1` | `172.17.0.1` — чтобы дотянулся чужой прокси из bridge-сети |

## Порты

80 и 443/tcp заняты чужим прокси, поэтому VPN уходит на свободные:

| Порт | Что |
|---|---|
| 80, 443/tcp | существующий reverse proxy — **не трогать** |
| 8443/tcp | VLESS + REALITY + Vision (основной канал) |
| 2087/tcp | VLESS + gRPC + REALITY (резерв) |
| 8444/udp | Hysteria2 (если 443/udp занят HTTP/3 чужого прокси) |
| 2222/tcp | внутренний API ноды, только из `172.16.0.0/12` |

`.env`:

```ini
SHARED_HOST=yes
CADDY_CONTAINER=<имя контейнера своего прокси>
XRAY_REALITY_PORT=8443
XRAY_GRPC_PORT=2087
HY2_PORT=8444
```

**Плата за это:** REALITY на нестандартном порту заметнее, чем на 443, где он
неотличим от обычного HTTPS. Как это исправить — в разделе «Self-steal» ниже.

## Что нужно добавить в существующий reverse proxy

Два блока. Правка аддитивная, существующие сайты не затрагивает.

```caddyfile
panel.traduzione.tech {
	reverse_proxy 172.17.0.1:3000
}

hy2.traduzione.tech {
	# Домен нужен только ради сертификата Let's Encrypt для Hysteria2.
	respond 404
}
```

После перезагрузки конфига прокси выпустит оба сертификата. Дальше сертификат
Hysteria2 забирается из его хранилища:

```bash
HY2_DOMAIN=hy2.traduzione.tech CADDY_CONTAINER=<имя> /opt/vpn/sync-certs.sh
```

Скрипт читает `/data/caddy/certificates` внутри контейнера, кладёт файлы
в `/opt/remnanode/ssl` и перезапускает ноду **только при реальной смене
сертификата**.

## Firewall

Скрипт его не трогает — правила добавляются самостоятельно, в той системе,
которая уже используется на сервере. Открыть наружу нужно `8443/tcp`,
`2087/tcp`, `8444/udp`. Порт ноды `2222/tcp` наружу открывать **нельзя**:
он должен быть доступен только из docker-сетей.

Если сервисы работают в docker с публикацией портов, помнить: опубликованные
порты идут через DNAT и цепочку `input` не проходят — правилами для `input`
их не закрыть.

## Риски совмещения

| Риск | Суть |
|---|---|
| Блокировка IP | Забанят адрес за VPN — вместе с ним отвалятся сайты на этом же IP |
| Ресурсы | Панель с PostgreSQL и Redis занимает 0.6–1 ГБ RAM у продакшена |
| Маскировка | REALITY не на 443 — заметнее при сканировании |
| Связанность | Перезапуск docker или правка firewall задевает и сайты, и VPN |

Если сайты важнее VPN — отдельный сервер за ~4 €/мес снимает все четыре пункта разом.

## Self-steal: вернуть REALITY на 443 (этап 2)

Схема, при которой Xray занимает 443, а существующий прокси работает за ним:
весь не-REALITY трафик Xray передаёт на `dest`, которым выступает тот же прокси.
Снаружи сервер отдаёт настоящие сайты с валидным сертификатом — маскировка лучше,
чем у любого выбранного чужого донора.

Что для этого нужно:

1. Перевести существующий прокси с `443` на внутренний порт (например `8443`).
2. В inbound REALITY указать `dest` на этот внутренний порт.
3. Включить PROXY protocol (`xver: 2` в `realitySettings` и приём proxy protocol
   на стороне прокси) — **иначе сайты будут видеть `127.0.0.1` вместо реальных
   IP посетителей**: сломается геолокация, антифрод, ограничение по частоте и логи.
4. Решить, что делать с HTTP/3: `443/udp` придётся отдать либо прокси, либо Hysteria2.

Это правка боевой конфигурации, поэтому делать её стоит отдельно и не спеша,
когда VPN уже работает на 8443.
