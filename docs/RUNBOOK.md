# RUNBOOK

Рабочие процедуры. Установка с нуля — [INSTALL.md](INSTALL.md), план и обоснования — [PLAN.md](PLAN.md).

## 1. Первый запуск

```bash
git clone <repo> /root/vpn && cd /root/vpn
cp .env.example .env && nano .env      # домены, ACME_EMAIL, SSH_ALLOW_IP
./bootstrap.sh
```

`bootstrap.sh` делает: пакеты и обновления, BBR+fq, лимиты, харденинг SSH, docker,
firewall (nftables), панель Remnawave за Caddy с Let's Encrypt, каталог ноды,
geo-файлы, cron на обновление списков и healthcheck.

Порядок дальше:

1. Открыть `https://<PANEL_DOMAIN>:8443`, создать администратора, **сразу включить 2FA**.
2. **Nodes → Create**: адрес `172.17.0.1`, порт `2222`.
   Выданный ключ вписать в `/opt/remnanode/.env`, затем
   `cd /opt/remnanode && docker compose up -d`.
3. Подобрать `REALITY_DEST` (см. §2) и записать в `.env`.
4. `./scripts/render-xray-template.sh` — соберёт готовый конфиг в
   `/opt/vpn/xray-config.json` и выведет значения для inbound'ов.
5. Вставить этот конфиг в шаблон Xray в панели.
6. Настроить подписку и профили (§4), создать первого пользователя (§5).

## 2. Подбор REALITY dest

Требования к сайту-донору:

- TLS 1.3, X25519, ALPN `h2`;
- физически в стране VPS (Финляндия/Германия), не за глобальным CDN;
- отдаёт контент без редиректа на другой домен;
- не заблокирован в РФ, не «затаскан» как популярный dest у публичных сервисов.

Проверка:

```bash
openssl s_client -connect example.com:443 -tls1_3 -alpn h2 -servername example.com </dev/null 2>&1 \
  | grep -E 'Protocol|Cipher|ALPN|Verify return'
```

Ожидаем `TLSv1.3`, `ALPN protocol: h2`, `Verify return code: 0`.

## 3. Guard-rails на сервере

Два варианта шаблона:

| Файл | Что блокирует | Когда брать |
|---|---|---|
| `config-template.json` | приватные сети, bittorrent, рекламу | по умолчанию |
| `config-template-ru-guard.json` | то же + `geosite:ru-available-only-inside` и `geoip:ru-whitelist` | когда профилем «Всё через VPN» никто не пользуется |

Смысл `ru-guard`: если клиент по ошибке отправит российский трафик в тоннель, он
не пойдёт молча с немецкого IP (что приводит к блокировкам в банках и на Госуслугах),
а отвалится с ошибкой — проблема станет видна сразу.

**Цена:** профиль «Всё через VPN» перестаёт открывать российские сайты. Это осознанный
размен, а не побочный эффект.

Категории берутся из `runetfreedom/russia-v2ray-rules-dat`, который кладёт
`scripts/update-geo.sh` в `/opt/remnanode/xray-assets`. Доступны в том числе:
`geosite:ru-blocked`, `geosite:ru-available-only-inside`, `geosite:category-ads-all`,
`geoip:ru-whitelist`, `geoip:ru-blocked`.

## 4. Профили, подписка и Happ

Панель отдаёт подписку на `https://<SUB_DOMAIN>:8443/api/sub/<short-uuid>`.

- **Templates → Xray-JSON** — формат конфига, который получает клиент.
  Правила роутинга едут внутри JSON, поэтому профили «Белые списки» / «Обходы» /
  «Всё через VPN» различаются именно здесь.
- **Subscription page** — страница, которую видит человек по ссылке: кнопки установки
  клиентов и импорт в один клик.
- **HAPP Routing** — встроенный в панель конструктор правил для Happ. Собранную ссылку
  вставить в поле `happRouting` настроек подписки; Happ применит правила сам.

Матрица профилей:

| Профиль | Inbound | Роутинг |
|---|---|---|
| `🇩🇪 Белые списки` | VLESS/TCP/REALITY/Vision | `ru-available-only-inside` + `geoip:ru-whitelist` → direct, остальное → proxy |
| `🇩🇪 Обходы` | тот же | `ru-blocked` → proxy, остальное → direct |
| `🇩🇪 Всё через VPN` | тот же | всё → proxy |
| `🇩🇪 Резерв gRPC` | VLESS/gRPC/REALITY, порт 2087 | как «Белые списки» |
| `🇩🇪 Резерв Hysteria2` | Hysteria2, UDP 443 | как «Белые списки» |

Первые три профиля используют один inbound — дополнительных ресурсов сервера не требуют.

> Проверить при настройке: категории вида `ru-blocked` требуют, чтобы у **клиента** были
> те же geo-файлы. Happ использует свои списки, поэтому для него надёжнее HAPP Routing,
> а кастомные категории оставить для sing-box, который умеет тянуть rule-set по URL.

## 4a. Hysteria2 — резервный канал

Hysteria2 реализован **внутри Xray-core** (`protocol: "hysteria"`, `version: 2`), поэтому
отдельный демон не нужен: inbound `HYSTERIA2` уже есть в шаблоне, пользователи и
статистика остаются в панели, а Happ поддерживает протокол штатно.

Зачем он нужен: основной канал — TCP. Когда оператор душит именно TCP-соединения или
рвёт длинные сессии, QUIC-канал часто продолжает работать. Обратная сторона — UDP в РФ
местами режут целиком, поэтому это именно **резерв**, а не замена REALITY.

### Схема портов

| Порт | Протокол | Что |
|---|---|---|
| 443/**tcp** | VLESS/REALITY/Vision | основной канал |
| 443/**udp** | Hysteria2 | резервный канал |
| 2087/tcp | VLESS/gRPC/REALITY | резерв для кривых сетей |

TCP и UDP на 443 не конфликтуют — это разные протоколы, слушают одновременно.

### DNS

`hy2.traduzione.tech` → A-запись на `178.105.192.76`, **проксирование Cloudflare выключено**
(серое облако). Cloudflare не проксирует UDP, с оранжевым облаком канал просто не поднимется.

Побочный эффект: этот поддомен раскрывает реальный IP сервера в DNS. Для панели это
по-прежнему не так (она за CF), а REALITY на TCP/443 своей маскировки не теряет.

### Сертификат

Hysteria2 требует настоящий TLS-сертификат. Caddy выписывает его для `HY2_DOMAIN`
(в Caddyfile под этот домен заведён отдельный блок, который отдаёт только 404),
а `sync-certs.sh` кладёт файлы в `/opt/remnanode/ssl` и **перезапускает ноду только если
сертификат изменился** — Xray читает cert при старте, а дёргать ноду ежедневно впустую нельзя.

Cron делает это дважды в сутки. Вручную:

```bash
HY2_DOMAIN=hy2.traduzione.tech /opt/vpn/sync-certs.sh
```

### Port hopping (опционально)

Клиент прыгает по диапазону UDP-портов, сервер редиректит их на 443 — помогает против
пер-портового шейпинга. Включается одной строкой в `.env`:

```
HY2_PORT_HOPPING=20000-20050
```

`bootstrap.sh` добавит правило `udp dport 20000-20050 redirect to :443` в nftables.
В клиенте порт указывается диапазоном.

### Проверка

```bash
ss -lnu | grep ':443'                  # сокет UDP поднят
docker logs remnanode --tail 50        # ошибки чтения сертификата видны здесь
ls -l /opt/remnanode/ssl/              # cert.pem и cert.key на месте
```

С клиента: переключиться на профиль Hysteria2 при выключенном основном и проверить выход
в сеть. Отдельно проверить на мобильном операторе — именно там резерв и понадобится.

### Известная особенность

В части сборок ноды Xray не отдаёт онлайн-статус для Hysteria2: **трафик считается
корректно, но пользователь показан офлайн** в панели. Это баг статистики Xray, а не канала.
Лечится обновлением ноды до сборки со свежим Xray:

```bash
cd /opt/remnanode && docker compose pull && docker compose up -d
```


## 5. Выдача доступа

1. **Users → Create**: метка, лимит трафика, срок действия, набор inbound'ов.
2. Отдать **ссылку-подписку** или deeplink, **не** голый `vless://` — при смене сервера,
   портов или ключей конфиг обновится у всех сам.
3. Для телефона — QR из панели.
4. Человек ставит Happ, открывает ссылку, выбирает профиль, жмёт кнопку.
5. Отзыв доступа — выключить пользователя в панели.

Правило: **отдельный пользователь на каждого человека**, а свои устройства — отдельными
пользователями либо одним с запасом по устройствам. Общий UUID на всех лишает смысла
статистику и делает отзыв доступа невозможным без затрагивания остальных.

## 6. Cloudflare

- A-запись поддомена панели → IP сервера.
- Проксирование (оранжевое облако) допустимо: порт **8443** входит в список
  проксируемых CF. Тогда реальный IP не виден в DNS.
- **Сертификат выпускать при выключенном проксировании** (серое облако), затем включать:
  ACME HTTP-01 ходит на порт 80 напрямую.
- Режим SSL — `Full (strict)`.
- На поддомен панели имеет смысл повесить правило доступа по стране или списку IP.

## 7. Приёмочные проверки

```bash
# слушаются нужные порты
ss -lntp | grep -E ':(443|2087|8443)\b'

# активное зондирование: должен отвечать сайт-донор, а не «пустота»
curl -Ik https://<IP сервера> | head -3

# BBR
sysctl -n net.ipv4.tcp_congestion_control

# ресурсы
docker stats --no-stream
```

С клиента:

- российский сайт видит домашний IP; открываются Госуслуги и банк-клиент;
- заблокированный ресурс открывается, `2ip.ru` показывает IP сервера;
- нет утечек DNS / WebRTC / IPv6;
- переключение Wi-Fi ↔ LTE не рвёт сессию;
- проверить на мобильном операторе отдельно — там DPI агрессивнее.

## 8. Обслуживание

| Что | Как | Когда |
|---|---|---|
| Списки блокировок | `/opt/vpn/update-geo.sh` | еженедельно, cron |
| Healthcheck | `/opt/vpn/healthcheck.sh`, алерты в Telegram | каждые 10 мин, cron |
| Обновление панели | `cd /opt/remnawave && docker compose pull && docker compose up -d` | по релизам |
| Обновление ноды | `cd /opt/remnanode && docker compose pull && docker compose up -d` | по релизам |
| Бэкап БД | `docker exec remnawave-db pg_dump -U postgres postgres \| gzip > backup.sql.gz` | перед каждым обновлением |
| Сертификат Hysteria2 | `/opt/vpn/sync-certs.sh` | дважды в сутки, cron |
| Обновление ОС | `apt update && apt full-upgrade` | ежемесячно |
| Трафик | `vnstat -m` | контроль лимита 20 ТБ |

Алерты в Telegram включаются заполнением `TG_TOKEN` и `TG_CHAT` в `/opt/vpn/healthcheck.env`.

## 9. Аварийные сценарии

**IP забанен в РФ.** Снапшот → новый сервер → `bootstrap.sh` → восстановить дамп БД →
в панели поменять адрес инбаунда. Ссылки-подписки у всех остаются рабочими — в этом
и был смысл раздавать подписку, а не голые конфиги.

**Панель недоступна снаружи.** Доступ через SSH-туннель:
`ssh -L 8080:127.0.0.1:3000 root@<IP>` → `http://127.0.0.1:8080`.

**Нода красная в панели.** `docker logs remnanode --tail 100`. Частые причины:
неверный ключ в `/opt/remnanode/.env`, порт 2222 закрыт firewall'ом для docker-сетей,
ошибка в шаблоне Xray (панель покажет её в логе ноды).

**Xray не стартует после правки шаблона.** Почти всегда — опечатка в имени geo-категории.
Проверить, что категория есть в `/opt/remnanode/xray-assets`, и что файлы обновились.

**Сертификат не выпускается.** `docker logs caddy --tail 50`. Проверить: A-запись,
проксирование CF выключено на время выпуска, порт 80 открыт в nftables.

**Hysteria2 не подключается.** По порядку: A-запись `HY2_DOMAIN` без проксирования CF;
`ss -lnu | grep :443` показывает сокет; `/opt/remnanode/ssl/cert.pem` существует и свежий;
в клиенте адрес — именно `HY2_DOMAIN`, а не IP (иначе не сойдётся имя в сертификате).
Если UDP режет оператор — включить port hopping.
